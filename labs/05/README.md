# Lab 05 · 錯誤診斷

## 情境說明

旅遊助理在回答問題時，不只要找到「相關的文件」，還要確保找到的文件加在一起能「完整回答問題」。例如問「旅館取消免費期限是多少、最晚幾點入住」這個問題，光找到 D5（72 小時取消政策）還不夠，還必須找到 D6（入住截止 15:00）才算完整。更麻煩的是，資料庫裡還混有已過時的 D4（舊版 48 小時政策）。這個 Lab 要你診斷現有系統在哪些情況下會失敗，並學習如何區分「找到了但不完整」與「根本不可回答」這兩種不同的失敗模式。

## 你會學到什麼

- 「證據完整率」與「決定正確率」是兩個不同的指標，不能混為一談
- 如何用「oracle 標註」（已知正確答案）來診斷系統失敗的原因
- 什麼是「不可回答問題」（unanswerable question），以及系統應該如何處理
- 信心門檻（confidence threshold）的作用：設太高則過度謹慎，設太低則容易出錯

## 可能卡住的地方

- **前三筆 k=2 案件都缺完整證據，這代表什麼？** 缺完整證據的意思是系統雖然找到了一些文件，但拼不出完整答案。想想：在 k=2 的限制下，Q1、Q2、Q3 各自缺了哪一份文件？
- **「oracle 示範」和「實際排名」的差異在哪？** oracle 是假設系統已知哪些文件是正確答案，然後看用這些文件能答到什麼程度。這個對比能說明什麼？
- **當門檻下沒有任何文件被放行時，`risk` 的值為什麼是 `null`？** 試著想：如果系統連一份文件都不確定，它應該說「我不知道」還是猜一個答案？
