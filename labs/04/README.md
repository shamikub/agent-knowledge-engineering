# Lab 04 · 證據排名

## 情境說明

旅途中累積了許多分散的文件：夜車票券、各城市的住宿確認、取消政策、餐廳訂位等。當你問「旅館取消政策和最晚入住時間」這類問題時，系統需要從這堆文件裡找出最相關的幾份作為回答依據。但有個麻煩：資料庫裡同時存有舊版取消政策（D4，48 小時）和現行版本（D5，72 小時），如果系統把舊版排在前面，你可能因為看錯條款而損失訂金。這個 Lab 要你實作並調整文件排名系統，確保正確的證據能排在最前面。

## 你會學到什麼

- BM25 關鍵字排名的原理：為什麼有些詞的權重比其他詞高
- 什麼是 nDCG（Normalized Discounted Cumulative Gain），以及如何用它衡量排名品質
- 如何用「過濾舊版文件」來避免系統回傳過時資訊
- 如何用 Reciprocal Rank Fusion（RRF）把兩個不同的排名融合成一個更好的排名

## 開始前確認

- 已讀完 [第 4 章講義](../../lectures/chapter4/intro.md)（資訊檢索與 RAG）
- 了解 TF-IDF 或 BM25 的基本概念（詞頻、逆文件頻率）
- 知道什麼是「相關性判斷」（relevance judgment）以及 qrels 格式

## 執行方式

從倉庫根目錄執行下列指令，觀察基線輸出：

```bash
python3 course.py 04
```

執行後你會看到三個查詢（Q1、Q2、Q3）的前 k 筆排名結果。接著根據 [SPEC](SPEC.md) 調整 k 值、過濾舊文件、並實作 RRF 融合，再核對 [EXPECTED](EXPECTED.md)。

## 可能卡住的地方

- **Q1 在 k=2 時為什麼會漏掉 D1？** 試著看 Q1 的查詢詞是什麼，BM25 給 D1 的分數和 D2 的分數哪個高，哪個被擠出 top-2。
- **為什麼 Q2 未過濾時 D4 會排第一？** D4 是舊版取消政策，它的文字和查詢詞的重疊程度可能比 D5 還高。想想「文件跟查詢詞有多像」和「文件是否最新」是兩個不同的問題。
- **Character bigram 排名和詞語排名有什麼不同？** 中文查詢用「字」來切還是用「詞」來切，對排名結果會有什麼影響？試著把「巴塞隆納」和「Barcelona」都加進查詢詞看看。

## 驗收標準

核對 [EXPECTED.md](EXPECTED.md)，重點確認：

1. Q1：k=2 時漏掉 D1，k=3 時 D1 補回排名
2. Q2：過濾舊版後，D4 不再出現，D5 和 D6 都在結果內
3. Q3：k=2 的 nDCG 為 1，但完整證據仍少一條（說明 nDCG 高不代表召回率完整）
