# Lab 03 · 延誤影響

## 情境說明

行程中有一段從某城市前往薩爾斯堡的火車，住宿規定旅客最晚必須在晚上 21:00 前抵達辦理入住，逾時將被換到其他房間。另外，羅騰堡那段火車班次則比較彈性，你可以自由選擇幾點搭。現在假設火車延誤了：延誤 0 分鐘、25 分鐘、35 分鐘，分別會對後續行程產生什麼影響？有些限制是硬性的（有截止時間），有些是未知的（例如行李寄放的關門時間），有些只是個人偏好。這個 Lab 要你把這三種情況分清楚，並建立一個可以追蹤「抵達→入住→換房」連鎖影響的知識結構。

## 你會學到什麼

- 如何區分「硬性截止」、「資訊未知」與「彈性偏好」三種不同類型的限制
- 如何用決策表（decision table）整理延誤影響，讓不同情境一目了然
- 如何用 SQLite recursive CTE 或 RDFLib 表達事件之間的連鎖關係（例如：延誤→超時→換房）
- 資訊壓縮（固定字數摘要）的副作用：移除數字可能改變原始意思

## 開始前確認

- 已讀完 [第 3 章講義](../../lectures/chapter3/intro.md)（規則、圖譜、時間與壓縮）
- 了解什麼是關係型資料庫的 CTE（Common Table Expression）或 RDF 三元組
- 能在紙上畫出「如果 X 則 Y」的簡單決策表

## 執行方式

從倉庫根目錄執行下列指令，觀察基線輸出：

```bash
python3 course.py 03
```

執行後你會看到三種延誤情境（0 分鐘、25 分鐘、35 分鐘）各自的影響判斷。接著根據 [SPEC](SPEC.md) 建立決策表並擴充知識圖，再核對 [EXPECTED](EXPECTED.md)。

## 可能卡住的地方

- **延誤 25 分鐘與延誤 35 分鐘，哪裡不同？** 薩爾斯堡住宿的 21:00 截止時間是關鍵，想想火車原本幾點抵達，加上延誤後還能不能在截止前到。
- **「行李寄放關門時間未知」對程式輸出代表什麼？** 這筆資訊的缺失應該被系統回報出來，而不是靜悄悄地被忽略或假設成某個預設值。
- **recursive CTE 或 RDF 三元組的「連鎖查詢」是什麼意思？** 試著用自然語言描述：「我想知道，哪些事件最終會導致換房？」再想如何把這個問句翻成資料庫查詢或圖查詢。

## 驗收標準

核對 [EXPECTED.md](EXPECTED.md)，重點確認：

1. 延誤 0 分鐘與 25 分鐘都在 21:00 截止限制內，不觸發換房
2. 延誤 35 分鐘超過截止時間，系統判斷需要重查住宿
3. 行李寄放關門時間標記為「未知」
4. 知識圖查詢可以從「影響」出發，經由「入住」找到「換房」節點

驗收指令：

```bash
python3 course.py 03
python3 -m unittest discover -s tests -v
```
