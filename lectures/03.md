# 知識表示、版本與壓縮

## Week 5 · 表、圖與規則
DMN 的決策表由條件和輸出組成。Unique 要求至多一列命中，First 按列優先順序選擇，Collect 蒐集多個命中。FEEL 讓時間、數字和區間可被機器計算。「不知是否能延後」應保存為未知，避免和「不能延後」套同一分支。

RDF 用主詞、述詞、受詞表示陳述。SPARQL 以圖樣比對查關係，SHACL 檢查必要欄位及形狀，PROV-O 可以表示衍生關係。Property Graph 允許把屬性放在節點與邊。當查詢是「改哪一段會影響哪些憑證」，從行程項目沿 dependsOn 邊遍歷。SQLite 也可用關聯表及 recursive CTE 做同一查詢。

## Week 6 · 時間與壓縮
Bitemporal 記 valid time 與 transaction time。例如取消政策 4/1 起有效，4/5 才匯入。重放 4/3 的助理決定時，必須以當時已知的版本還原。實作可用半開區間避免相鄰版本在邊界同時適用。

抽取式摘要選原句。RAPTOR 遞迴聚類與摘要以建立不同層級的索引。LongLLMLingua 縮減送入模型的上下文。比較固定 token 預算下完整證據保留率和答案品質。少掉一句「21:00 前」可能讓摘要更短，也讓任務失敗。

練習。畫出延誤 → 入住、入住 → 換房的兩條邊，補效期與來源，再查兩跳影響。加一個環並說明遍歷如何終止。

閱讀：[DMN](https://www.omg.org/dmn/)、[SHACL](https://www.w3.org/TR/shacl/)、[PROV-O](https://www.w3.org/TR/prov-o/)、[RAPTOR](https://arxiv.org/abs/2401.18059)、[LongLLMLingua](https://arxiv.org/abs/2310.06839)。前沿作業比較兩種壓縮方法，排齊 token 預算、回答模型和任務。

## 3.1 把自然語言落成可執行規則

「21:00 前到」與「最晚可在 21:00 入住」的邊界可不同。課程基線採後者。決策表要寫出輸入型別、比較關係、例外和來源。FEEL 表達時間、數字及區間。DMN hit policy 決定多列命中時怎麼辦。Unique 要求至多一條命中，First 依列順序，Collect 保留多項結果。

| 預計抵達 | 入住截止 | 處置 |
|---|---|---|
| 20:55 | 21:00 | 照原安排 |
| 21:10 | 21:00 | 向住宿確認 |
| 未知 | 21:00 | 補抵達時間 |
| 21:10 | 未知 | 查入住條件 |

遇到「通知就可晚到」的例外，新增有無旅館同意的欄位，把一般規則及例外做成互斥條件，再試 20:59、21:00、21:01 和未知。條文保留上下文與措辭，表格適合有限輸入下的明確決策。若條件依賴一段開放式描述，可先萃取帶來源的欄位。

## 3.2 把關係存起來再查

建兩筆三元組 trainA affects checkin、checkin affects roomChange。SPARQL 以變數比對圖樣，可用 affects+ 取至少一跳。查 trainA 會找到 checkin 和 roomChange。SHACL 檢查例如每項訂位至少有一個來源。PROV-O 的 wasDerivedFrom 指向輸入證據。多個版本或互相衝突的陳述，可各自留在具名圖再按有效版本查。Property Graph 可把時間與來源直接放在邊上。

同一查詢可用 SQLite 的 edge 表和 recursive CTE。遍歷用 UNION 去重或記錄已訪問節點，否則 A→B→A 可持續展開。關聯資料容易整合交易和約束，圖譜適合多種關係、多跳查詢與跨資料語意。兩個工具都能查上述例子，選型要量查詢頻率、資料更新與維護成本。

## 3.3 版本的兩個時鐘

新政策 4/1 起生效，系統 4/5 才得知。今天查「4/3 哪條有效」須比 valid time。重播「系統在 4/3 看得到哪條」還須限制 transaction time。修正時保留舊記錄才能回答歷史問題。可使用半開區間，避免兩個相鄰版本在同一秒都有效。跨日時須先確認時區。以不同城市的抵達、出發時間驗證當地日期和 UTC 時間的轉換。

## 3.4 壓縮的收益與資訊遺失

抽取式摘要挑原句。RAPTOR 將段落嵌入並聚類，摘要群組、遞迴形成索引層級。廣泛問題可召回上層摘要，數字或例外仍可回查葉節點。LongLLMLingua 在檢索後按問題相關性裁剪上下文。前者改變候選怎麼找，後者改變候選有多少內容可供模型用。

**算例。** 一題需要 21:00 截止、延遲 35 分鐘、旅客 A 照常入住。120 token 壓成 45，節省 62.5%。若剩兩個必要事實，事實召回是 2/3，完整證據命中是 0。除了 token 預算，也報告數字、否定和例外的保留率。

**實驗。** Lab 03 用一張表與一張圖各查一次延誤的兩跳影響。再固定字數比較直接截斷與保留條件句。記下因壓縮而從「可判定」變成「需要確認」的案例。
