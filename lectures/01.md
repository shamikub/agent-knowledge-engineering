# 文件、語音與流程探勘

## Week 1 · 從訊號到證據
文件理解包含文字辨識、版面分區、閱讀順序、表格列欄復原。文字型 PDF 可先讀文字層，掃描需 OCR。LayoutLMv3 結合字詞、框的位置和影像 patch 進行預訓練。Table Transformer 用物件偵測模型標表格與表格結構。拿「住宿欄跨兩列」作例子，文字全認對仍可能把洗衣設備掛錯住宿。OCR 可用 CER（字元編輯距離除以參考字數），表格另外量儲存格對齊與結構。

Whisper 做語音轉文字。WhisperX 以 forced alignment 對齊字詞時間，搭配 diarization 把片段分給講者。逐字稿字對了，仍可能判錯發言人。操作證據優先考慮應用程式事件；rrweb 重播 DOM，Accessibility Tree 表達介面語意。實際輸入保留來源定位和事件時間。

## Week 2 · 流程發現與一致性
流程發現從事件日誌推模型。一個 case 可是一筆訂位。OCEL 2.0 允許同一事件同時關聯車票、旅客和整趟旅程。Directly-follows graph 統計緊鄰活動；Alpha Miner 用先後關係辨識流程結構，Heuristics Miner 用頻率和相依度處理噪音，Inductive Miner 遞迴尋找循序、選擇、平行或迴圈的切分並生成流程樹。觀察到「取消 → 重訂」證明兩個步驟相鄰，原因仍需來源補足。

Alignment 把觀察軌跡對齊模型行為。Fitness 量觀察記錄能否被模型重現，precision 懲罰模型容許太多未觀察行為。讓所有動作都能任意發生，fitness 可能很好，precision 會下降。

練習。對 AB、AC、ABC 三條軌跡手算邊的頻次。刪去 ABC 後解釋 B→C 消失的含義。

閱讀：[LayoutLMv3](https://arxiv.org/abs/2204.08387)、[PubTables-1M](https://arxiv.org/abs/2110.00061)、[WhisperX](https://arxiv.org/abs/2303.00747)、[OCEL 2.0](https://www.ocel-standard.org/)、[PM4Py](https://processintelligence.solutions/static/api/2.7.17/api.html)。前沿作業挑文件版面或表格辨識，查一個公開資料集上同一指標的兩個結果。

## 1.1 文件解析的每一層

PDF 的文字層可能是一組帶座標的字元。畫面可正常顯示，抽取時卻會把左右欄交錯。掃描 PDF 要先轉影像。依序看文字區域偵測、裁切和方向校正、字串辨識、閱讀順序與表格重建。每個輸出保留頁號、邊界框、文字與信心，才能分辨是漏認文字，還是認對但放錯列。

LayoutLMv3 把文字 token、二維位置與影像 patch 一起送進 Transformer。遮蔽文字、遮蔽影像和詞與影像 patch 對齊讓模型學到「這個詞在哪裡、旁邊長什麼樣」。下游可從 token 表示預測欄位類別。Table Transformer 把列、欄、標頭當物件來偵測，再用字框位置重建儲存格。遇到跨欄標頭時，還需保留儲存格跨度與閱讀順序。

**算例。** 參考文字是「洗衣機 烘衣機」，忽略空白後，漏了「烘」的 CER 是 1/6。另一個工具六字全對，卻把烘衣機配到下一間住宿，CER 仍是 0。加入儲存格對齊與欄位正確率，才會抓到第二種錯。

| 輸入 | 先試 | 要驗證的失敗 |
|---|---|---|
| 格式固定、有文字層的票券 | 文字座標加模板 | 改版後欄位是否移位 |
| 模糊掃描、多欄頁面 | OCR 與版面分析 | 旋轉或混排是否打亂順序 |
| 跨欄表格 | 結構辨識與字框對位 | 住宿與設施是否配錯 |

## 1.2 音訊與操作的事件證據

Whisper 把音訊轉成 log-Mel 頻譜，編碼器形成上下文表示，解碼器根據該表示與已生成 token 逐步輸出文字。WhisperX 用 forced alignment 將轉錄字詞對上音訊區間，再與 diarization 的講者片段合併。轉錄、對齊和講者辨識要各自驗收。WER 對文字編輯距離，DER 量講者分段錯誤，決議萃取還要核對講者是否同意、否定或改口。

00:10 A 說「那就先取消」，00:12 B 說「先等回信」。如果只存「取消住宿」就丟了決議仍待定的證據。存音訊區間、講者、原話與轉錄版本，候選決議另外進人工佇列。

瀏覽器的 click 只證明按了按鈕，後端 booking.updated 才能驗證資料寫入。用 case ID 串起操作前狀態、動作與後端結果，區分事件發生時間與到達時間。rrweb 可重播頁面狀態，Accessibility Tree 可描述欄位和按鈕語意。資料採集先問「我要分辨哪兩種狀態」，例如送出成功和送出失敗，再決定需要哪路訊號。

## 1.3 從軌跡到流程樹

Directly-follows graph 統計相鄰活動。Alpha Miner 用先後關係推因果與並行，對短迴圈和未觀察到的路徑敏感。Heuristics Miner 用相依度與頻數抗噪音，過高門檻會捨棄罕見取消流程。Inductive Miner 找循序、互斥、並行或迴圈切分，再對各子日誌遞迴，直到單一活動等基底。流程樹可轉 Petri net 做一致性檢查。

**走一遍切分。** 軌跡 ABC、ADC 先切 A、{B,D}、C，再把中間切成互斥選擇。加入 ABDC 後，B 與 D 能同時出現，互斥假設要重查。若模型預期 A→B→C、實際 A→C，alignment 會對齊 A 和 C，中間以一個 model move 表示缺 B。那一步可能真的跳過，也可能是事件漏記。

**實驗。** Lab 01 刪掉取消事件，寫出兩條變動的相鄰邊。再比較 DFG 與 PM4Py 流程樹能表達的資訊。保留罕見取消路徑加入驗證集，觀察 fitness 和 precision 的取捨。
