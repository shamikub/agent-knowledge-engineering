# 資訊檢索與 RAG

## Week 7 · 第一階段候選
倒排索引列出每個詞所在文件。BM25 對每個查詢詞累加 IDF × tf(k1+1)/(tf+k1(1-b+bL/avgL))。詞頻飽和避免重複某詞就無限加分，長度正規化處理長文件的匹配偏差。SPLADE 學習稀疏詞彙權重，DPR 和 E5 以雙編碼器產生查詢與文件向量。歐洲地名與中文別名是觀察字面匹配和語意匹配差異的好例子。

## Week 8 · 融合、重排與多跳
RRF 對文件加總 1/(c+rank)，只需可比較的名次。ColBERTv2 為查詢 token 尋找文件中的最大相似度再加總。Cross-encoder 聯合編碼每組 query/document，通常用於候選重排。候選先被漏掉，重排沒有機會補回。日期、版本、來源權限可先作 metadata filter。結合兩份跨文件證據時，qrels 要包括主條款與適用例外。

Recall@k 是找回的相關證據比例。nDCG@k 對相關性作排名折扣並除以理想 DCG。完整集合命中率要求至少一組足夠證據完整出現在前 k 筆。若答案要求三筆，k=2 絕不可能完整。

練習。列表 A=[X,Y]、B=[Y,Z]，手算 c=60 的分數。把 Z 補進 gold，檢查 top 2 有無完整命中。

閱讀：[DPR](https://arxiv.org/abs/2004.04906)、[SPLADE](https://arxiv.org/abs/2107.05720)、[E5](https://arxiv.org/abs/2212.03533)、[ColBERTv2](https://arxiv.org/abs/2112.01488)、[BEIR](https://arxiv.org/abs/2104.08663)、[MIRACL](https://arxiv.org/abs/2210.09984)。前沿作業挑一個語言與固定切分，核對候選模型、reranker 和訓練資料。

## 4.1 從字元到倒排索引

給定「夜車 洗衣」和兩份預先切詞的文件，系統先建立詞彙表，再將每個詞映射至含有它的文件，以及在該文件內的次數。這個列表稱為 postings list。查詢時可走「夜車」及「洗衣」的 postings，對聯集評分。中文若沒有預先切詞，要先定義粒度，例如詞、字或 bigram。切詞會直接決定哪些查詢有機會命中。地名「波多」和「波爾圖」分到不同 token 時，可加入別名或換表示法。

最簡單的模型是詞重疊。假如一份文件把「洗衣」重複 20 次，重疊計數可能壓過只寫一次的精準訂位信。TF-IDF 按詞在文件內的出現量及跨文件的稀有度加權。BM25 進一步讓詞頻的貢獻飽和，並依文件長度調整。實作時，索引存 postings，查詢時計算分數，最後取 top-k。Lucene 等引擎會替你處理這些步驟，分析器與欄位權重仍需由你選。

## 4.2 拆開 BM25 的每個零件

對詞 t，TF 是同一份文件出現幾次，DF 是有幾份文件含它。令 N 為文件數，採本課版本：

```text
IDF(t) = log(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
K      = k1 * (1 - b + b * 文件長度 / 平均文件長度)
score  = Σ IDF(t) * TF * (k1 + 1) / (TF + K)
```

- TF 為 0，詞貢獻為 0。當 TF 越來越大，該部分逼近 k1 + 1。
- b=0 時，K 不看文件長度。b 越大，對同樣詞頻的長文件扣分越多。
- DF 高的詞 IDF 低。「旅館」可能幾乎每封信都有，「烘衣機」比較有辨識力。

**算一遍。** 假設只有兩份文件，長度分別是 2 與 6，平均 4，兩份都只提一次「烘衣機」。k1=1.2、b=0.75，得到 K=0.75 和 1.65，IDF 約 0.182。兩份分別得約 0.229 和 0.151。若 b=0，兩份同得約 0.182。拿 course.py 的 bm25 對照每一項放在哪一行。

**適用場景。** 訂位代碼、正式條款用語與稀有地名，往往需要精確匹配。優點是快、成本低、可解釋。缺點是同義詞、跨語言和切詞錯誤容易造成漏檢。SPLADE 用 Transformer 為詞彙產生權重，可對原文未出現的詞給權重，依然能用倒排索引，但多了模型推論與索引膨脹成本。

## 4.3 向量檢索從哪裡得到語意

先把句子切成 token，查 embedding 表取得一串向量。Transformer 的 self-attention 用每個 token 的 query、key、value 計算要參考哪些位置，讓同一個「房」在「雙人房」與「房間取消政策」得到不同的上下文表示。接著以 pooling 產生固定長度向量。E5 有配套的 query 和 passage 前綴，實作要依模型卡處理。

Dual encoder 分開編碼查詢與文件。可以把文件向量預先算好，查詢時比較 dot product 或 cosine。向量正規化時，兩者排名相同。對比訓練把正例拉近、負例推遠。若負例都是毫不相干的文件，模型可能沒學會分辨「有洗衣機」和「可以洗也可以烘」。拿詞彙相近、條件不合的住宿當 hard negative，訓練訊號會更接近任務。

**算一遍。** 查詢向量 (1,0)，兩份文件 (2,0) 與 (4,3)。dot product 得 2 與 4，cosine 得 1 與 0.8，排名相反。比較結果前先核對 normalization 和距離函數。小型資料可以直接掃過所有向量，大型資料才比較 HNSW 等近似近鄰索引，並以 exact search 量索引本身漏掉多少候選。

**適用場景。** 口語改寫、跨語別名、相似案件檢索。優點是能找回字面差很遠的文件。代價是需要編碼和儲存向量，模型可能把「已取消」與「可取消」、新舊版本都排得很近。版本、生效日期和權限仍要用適用條件查核。

## 4.4 從候選到重排

**Cross-encoder。** 把 query 和 document 串在同一次前向運算，讓詞和詞直接互相注意。它有機會辨認「能洗也能烘」中的兩個條件是否同時成立。每組都要重算，通常只跑在前 k 筆。若 BM25 或向量檢索都漏了 D1，重排序也找不回來。

**ColBERT。** 查詢和文件可以分開編碼，但保留 token 向量。查詢中的每個 token 從文件找最大相似度，再加總。例如兩個查詢 token 對文件 token 的相似度分別是 [0.9, 0.1] 和 [0.4, 0.8]，MaxSim 得 1.7。相較單向量能保存細部對齊，代價是更大的索引與打分量。

**RRF。** 把不同排名的倒數名次相加，不必先對齊 BM25 和 cosine 的分數尺度。共同前排通常會受益。它也可能把兩路都偏愛的舊版條款推更高，所以不能替代時間過濾。

| 需求 | 優先試哪一種 | 怎麼知道該換 |
|---|---|---|
| 查航班代碼、規則用語 | BM25 | 測別名與自然語言改寫的 Recall@k |
| 用口語找相近段落 | 小型多語 E5 | 看精確代碼與否定條件是否掉排名 |
| 兩種錯誤各有互補 | BM25 + E5 + RRF | 同 k 回報完整證據命中與延遲 |
| 候選已齊，順序不佳 | Cross-encoder | 同候選集量排序差異和單案成本 |
| 想保留細粒度詞匹配 | ColBERT | 比排序收益、索引大小和查詢時間 |

## 4.5 從檢索到回答

「現在取消會不會被收費」至少涉及訂位時間、現行取消條款和當下時間。先用 metadata 選適用版本，再找兩段證據，最後把時間比較交給確定性的程式。標註 qrels 時同時記錄哪些文件單獨相關、哪些組合才足以回答。量三層：候選是否齊全、回答是否正確、引用是否支持結論。

**驗收反例。** Q3 在 k=2 時 nDCG 可以是 1，因為前兩名都相關，但回答需要三份文件。再用同一筆案例比較 k=3，並執行含舊條款與不含舊條款的對照。注意一筆錯答可能是主要證據遺失，也可能是檢索齊了但選用過期規則。

**研究討論。** 固定 BEIR 或 MIRACL 單一切分，比一個稀疏和一個 dense 方法。記錄語言、訓練集合、是否重排、指標和日期。再回到旅行資料做一次失敗分析，找出公開榜單沒有測到的時態或版本問題。
