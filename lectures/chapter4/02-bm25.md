# 4.2 拆開 BM25 的每個零件

## 學習目標

讀完本節後，你應該能：

- 說明 BM25 解決了 TF-IDF 的哪兩個問題（詞頻飽和、長度正規化）
- 手算一個查詢對三份文件的 BM25 分數，並說明每一步的來源
- 解釋 k1 和 b 這兩個參數的物理意義，以及調高調低各有什麼效果
- 比較 BM25 與 TF-IDF 的本質差異
- 說明 BM25 在哪些情境下會失敗，以及 SPLADE 的位置

**先備知識：** 對數運算、4.1 節的倒排索引概念。

---

## 任務定義：排名而非布林

布林查詢只回答「符合 / 不符合」，所有符合的文件地位相同。現實中使用者需要的是**排名（ranking）**：有十份文件都提到「取消政策」，哪一份最有可能回答你的問題？

BM25（Best Match 25）是**排名檢索（ranked retrieval）**的標準基線，輸入一個自然語言查詢，對每份文件算出一個分數，再取 top-k。

| 項目 | 說明 |
|------|------|
| 輸入 | 查詢 q（切詞後的 token 序列）、文件集合 D |
| 輸出 | 每份文件的分數，用以排序取 top-k |
| 核心思路 | 稀有詞貢獻高（IDF）、詞頻有飽和上限（k1）、長文件做長度懲罰（b） |

---

## 公式與每個符號的意義

對查詢 q 和文件 d，BM25 分數為：

```text
score(q, d) = Σ_{t ∈ q}  IDF(t) × TF_norm(t, d)

其中：

IDF(t) = log( 1 + (N - DF(t) + 0.5) / (DF(t) + 0.5) )

TF_norm(t, d) = TF(t, d) × (k1 + 1) / ( TF(t, d) + K )

K = k1 × ( 1 - b + b × |d| / avgdl )
```

**符號對照表：**

| 符號 | 名稱 | 說明 |
|------|------|------|
| N | 文件總數 | 語料庫大小 |
| DF(t) | 文件頻率（Document Frequency） | 含詞 t 的文件數 |
| TF(t, d) | 詞頻（Term Frequency） | 詞 t 在文件 d 出現幾次 |
| \|d\| | 文件長度 | 文件 d 的 token 數 |
| avgdl | 平均文件長度 | 整個語料庫的 token 數平均值 |
| k1 | 詞頻飽和參數 | 預設 1.2，控制 TF 的飽和速度 |
| b | 長度正規化參數 | 預設 0.75，0 = 不看長度，1 = 完全正規化 |

---

## k1 和 b 的直觀解釋

### k1：詞頻飽和

TF_norm 的分子是 `TF × (k1 + 1)`，分母是 `TF + K`。當 TF 趨向無窮大時，整個分數趨近 `k1 + 1`。k1 決定「詞出現多次比一次多多少分」。

```text
k1 = 1.2，K = 1（固定，忽略長度效果）：
TF=1 → 1 × 2.2 / (1 + 1) = 1.10
TF=2 → 2 × 2.2 / (2 + 1) = 1.47
TF=5 → 5 × 2.2 / (5 + 1) = 1.83
TF=10 → 10 × 2.2 / (10 + 1) = 2.00  ← 趨近飽和上限 k1+1 = 2.2
TF=∞ → 2.2
```

**k1 越大**：飽和越慢，高頻詞的文件優勢越大。
**k1 越小**：趨近二元（出現或不出現），接近 BM11。

### b：長度正規化

K = k1 × (1 - b + b × |d| / avgdl)

- **b = 0**：K = k1，完全不看文件長度。長文件和短文件的詞頻效果相同。
- **b = 1**：K = k1 × |d| / avgdl，完全按比例縮放。短文件的詞頻等效地更高。
- **b = 0.75**（預設）：折中。長文件仍有輕微的詞頻懲罰。

**數字說明：** 若 avgdl = 100、k1 = 1.2、b = 0.75：
- 短文件（|d|=50）：K = 1.2 × (0.25 + 0.75 × 0.5) = 1.2 × 0.625 = 0.75
- 長文件（|d|=200）：K = 1.2 × (0.25 + 0.75 × 2) = 1.2 × 1.75 = 2.10

同樣是「TF=2」，短文件的 TF_norm = 2 × 2.2 / (2 + 0.75) = **1.60**，長文件的 TF_norm = 2 × 2.2 / (2 + 2.10) = **1.07**。長文件被合理地懲罰了。

## 完整算例：三份文件、兩個查詢詞

### 資料設定

```text
N = 3 份文件

D1（訂位確認信，5 tokens）：「確認 訂位 含 洗衣機 服務」
D2（住宿說明，8 tokens）：「房型 提供 洗衣機 烘衣機 洗衣機 費用 另計 預約」
D3（取消政策，6 tokens）：「取消 訂位 48 小時 前 辦理」

avgdl = (5 + 8 + 6) / 3 = 6.33
k1 = 1.2，b = 0.75
```

**查詢：「洗衣機 訂位」**（查詢詞 t1 = 洗衣機、t2 = 訂位）

### 步驟一：計算 IDF

```text
「洗衣機」出現在 D1、D2，DF = 2
IDF(洗衣機) = log(1 + (3 - 2 + 0.5) / (2 + 0.5))
            = log(1 + 1.5 / 2.5)
            = log(1 + 0.6)
            = log(1.6)
            ≈ 0.470

「訂位」出現在 D1、D3，DF = 2
IDF(訂位) ≈ 0.470（同上，DF 相同）
```

### 步驟二：計算每份文件的 K

```text
D1（|d|=5）：K₁ = 1.2 × (1 - 0.75 + 0.75 × 5/6.33)
                 = 1.2 × (0.25 + 0.593)
                 = 1.2 × 0.843 = 1.012

D2（|d|=8）：K₂ = 1.2 × (0.25 + 0.75 × 8/6.33)
                 = 1.2 × (0.25 + 0.948)
                 = 1.2 × 1.198 = 1.438

D3（|d|=6）：K₃ = 1.2 × (0.25 + 0.75 × 6/6.33)
                 = 1.2 × (0.25 + 0.711)
                 = 1.2 × 0.961 = 1.153
```

### 步驟三：計算每個詞對每份文件的貢獻

**詞「洗衣機」：**

```text
D1：TF=1，TF_norm = 1 × 2.2 / (1 + 1.012) = 2.2 / 2.012 ≈ 1.093
    貢獻 = 0.470 × 1.093 ≈ 0.514

D2：TF=2，TF_norm = 2 × 2.2 / (2 + 1.438) = 4.4 / 3.438 ≈ 1.280
    貢獻 = 0.470 × 1.280 ≈ 0.602

D3：TF=0，貢獻 = 0
```

**詞「訂位」：**

```text
D1：TF=1，TF_norm = 1 × 2.2 / (1 + 1.012) = 2.2 / 2.012 ≈ 1.093
    貢獻 = 0.470 × 1.093 ≈ 0.514

D2：TF=0，貢獻 = 0

D3：TF=1，TF_norm = 1 × 2.2 / (1 + 1.153) = 2.2 / 2.153 ≈ 1.022
    貢獻 = 0.470 × 1.022 ≈ 0.480
```

### 步驟四：加總分數與排名

```text
D1：0.514 + 0.514 = 1.028   ← 兩個詞都有，排第一
D2：0.602 + 0     = 0.602   ← 只有洗衣機（且出現兩次），排第二
D3：0     + 0.480 = 0.480   ← 只有訂位，排第三
```

**排名：D1 > D2 > D3**

D1 因為同時含兩個查詢詞且文件較短，分數最高，符合直覺。

---

## 當 b = 0 時會怎樣？

以 D1 和 D2 對「洗衣機」的貢獻為例：

```text
b=0 → K = k1 = 1.2（所有文件一樣）

D1：TF=1，TF_norm = 2.2 / (1 + 1.2) = 1.000，貢獻 = 0.470
D2：TF=2，TF_norm = 4.4 / (2 + 1.2) = 1.375，貢獻 = 0.646
```

D2 因為詞頻更高（出現兩次）而領先 D1 更多。長度懲罰關閉後，重複一個詞多次的長文件更容易得高分。

## BM25 與 TF-IDF 的正式比較

| 比較項目 | TF-IDF | BM25 |
|----------|--------|------|
| 詞頻函數 | 線性（TF 越大分數越大） | 飽和型（趨近 k1+1 的上限） |
| 長度正規化 | 無（或用 cosine 正規化） | b 參數控制，可精確調整 |
| IDF 公式 | log(N / DF) | log(1 + (N - DF + 0.5) / (DF + 0.5)) |
| 超參數 | 無 | k1（預設 1.2）、b（預設 0.75） |
| 實驗支持 | 1970 年代 | TREC 實驗反覆驗證，業界首選基線 |
| 實作 | 自行計算 | Elasticsearch / Lucene 預設 |

BM25 在大多數任務上明顯優於 TF-IDF，調整成本低，仍是所有向量方法的對比基線。

## 適用場景與失敗模式

**適合用 BM25 的情況：**
- 訂位代碼、航班號、法規條款編號等精確術語
- 稀有的專有地名（如「薩爾斯堡中央車站」）
- 語言資源少、無法訓練 embedding 的情境

**BM25 的失敗模式：**
- **同義詞漏檢：** 查「烘衣設備」找不到只寫「烘衣機」的文件
- **跨語言：** 中文查詢無法匹配英文文件
- **切詞錯誤：** 「洗烘衣機」切成「洗烘」＋「衣機」，查「洗衣機」找不到
- **否定語意：** 「不含早餐」和「含早餐」對「早餐」這個詞的 BM25 分數相同

**SPLADE 的位置：** 用 Transformer 為詞彙產生權重，讓原文未出現的同義詞也能有貢獻，同時保留倒排索引的查詢速度。代價是額外的模型推論與索引膨脹（index bloat）。

## 習題

**題 1（手算）：** 假設 N=3，兩份文件都只提一次「烘衣機」（DF=2），文件長度分別是 2 和 6，avgdl=4，k1=1.2，b=0.75。算兩份文件對「烘衣機」的 BM25 分數（IDF × TF_norm），並說明為何短文件得分較高。

<details>
<summary>解答</summary>

```text
IDF = log(1 + (3 - 2 + 0.5) / (2 + 0.5)) = log(1.6) ≈ 0.182

D_short（|d|=2）：
  K = 1.2 × (1 - 0.75 + 0.75 × 2/4) = 1.2 × (0.25 + 0.375) = 1.2 × 0.625 = 0.75
  TF_norm = 1 × 2.2 / (1 + 0.75) = 2.2 / 1.75 ≈ 1.257
  score = 0.182 × 1.257 ≈ 0.229

D_long（|d|=6）：
  K = 1.2 × (0.25 + 0.75 × 6/4) = 1.2 × (0.25 + 1.125) = 1.2 × 1.375 = 1.65
  TF_norm = 1 × 2.2 / (1 + 1.65) = 2.2 / 2.65 ≈ 0.830
  score = 0.182 × 0.830 ≈ 0.151
```

短文件（0.229）高於長文件（0.151）。理由：同樣是「出現一次」，在短文件中這個詞的相對密度更高，b 參數讓 K 較小，使 TF_norm 較大。如果設 b=0，兩份文件的分數都等於 0.182 × 1.0 = 0.182，完全相同。

</details>

**題 2（概念）：** 一個旅遊問答系統發現：BM25 把「薩爾斯堡 Airbnb 規定」這筆查詢的前三名全排給含有大量「薩爾斯堡」的旅遊指南頁，而不是真正寫了 Airbnb 規定的那一份文件。可能的原因是什麼？你會怎麼調整？

<details>
<summary>解答</summary>

可能原因：「Airbnb」和「規定」在語料庫中很稀有（IDF 高），但旅遊指南頁字數多，「薩爾斯堡」多次出現，TF × (k1+1) / (TF+K) 累積起來高於含「Airbnb 規定」但「薩爾斯堡」只出現一次的文件。

調整方向：
1. 降低 b（減少長度懲罰），讓長文件不那麼有利。
2. 把「Airbnb 規定」這樣的稀有詞欄位提高欄位權重。
3. 在前處理確認「Airbnb」沒有被切詞工具切壞（例如切成「Air」「bnb」）。
4. 若語意仍無法對齊，考慮混合 BM25 + dense retrieval。

</details>

---

**題 3（選型）：** 你的語料庫有 10,000 份文件，其中 9,800 份都包含「旅館」這個詞。一個查詢只有「旅館」這一個詞。BM25 的排名結果是否有意義？為什麼？

<details>
<summary>解答</summary>

排名意義不大。「旅館」的 DF = 9800，IDF = log(1 + (10000 - 9800 + 0.5) / (9800 + 0.5)) = log(1 + 200.5 / 9800.5) ≈ log(1.020) ≈ 0.020。IDF 極低，代表這個詞幾乎沒有辨識力，所有含「旅館」的文件得分都很接近。

實際排名幾乎等同於按 TF 排，也就是哪份文件「旅館」出現最多次。這通常不是使用者要的答案。

解法：
- 在 BM25 加入更多查詢詞以提高辨識力（例如完整的查詢句）
- 用 stopwords 把高頻的業務詞（「旅館」、「服務」）移除或降低權重
- 切換到 dense retrieval，讓語意更豐富的查詢能找到更相關的文件

</details>
