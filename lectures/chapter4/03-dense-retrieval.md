# 4.3 向量檢索從哪裡得到語意

先把句子切成 token，查 embedding 表取得一串向量。Transformer 的 self-attention 用每個 token 的 query、key、value 計算要參考哪些位置，讓同一個「房」在「雙人房」與「房間取消政策」得到不同的上下文表示。接著以 pooling 產生固定長度向量。E5 有配套的 query 和 passage 前綴，實作要依模型卡處理。

Dual encoder 分開編碼查詢與文件。可以把文件向量預先算好，查詢時比較 dot product 或 cosine。向量正規化時，兩者排名相同。對比訓練把正例拉近、負例推遠。若負例都是毫不相干的文件，模型可能沒學會分辨「有洗衣機」和「可以洗也可以烘」。拿詞彙相近、條件不合的住宿當 hard negative，訓練訊號會更接近任務。

**算一遍。** 查詢向量 (1,0)，兩份文件 (2,0) 與 (4,3)。dot product 得 2 與 4，cosine 得 1 與 0.8，排名相反。比較結果前先核對 normalization 和距離函數。小型資料可以直接掃過所有向量，大型資料才比較 HNSW 等近似近鄰索引，並以 exact search 量索引本身漏掉多少候選。

**適用場景。** 口語改寫、跨語別名、相似案件檢索。優點是能找回字面差很遠的文件。代價是需要編碼和儲存向量，模型可能把「已取消」與「可取消」、新舊版本都排得很近。版本、生效日期和權限仍要用適用條件查核。
