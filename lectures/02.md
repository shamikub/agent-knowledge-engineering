# 資訊萃取與低負擔校對

## Week 3 · 文字如何變成事件
NER 找 mention，entity linking 判斷多個 mention 是否指同一個實體，事件抽取把動作、參與者、地點與時間填入 schema。用「我退掉 8 點那張，訂了 10 點」練習表示兩筆事件。CRF 可建模相鄰標籤，Transformer 用上下文表示每個 token，受限生成可強制輸出符合 schema 的 JSON。三種方法都要用 span 或欄位評估精確率和召回率。JSON 能解析，只驗證形狀。把「明天」轉日期需要發言時間與時區。

## Week 4 · 人工預算怎麼花
Snorkel 的 labeling functions 可以標類別或 abstain，label model 用多個弱訊號估計標籤。兩條規則若複製同一模板，當獨立票數會高估信心。主動學習可依 uncertainty、committee disagreement 或代表性（core-set）選件。分歧抽樣容易優先撈到異常樣本，仍需保留隨機抽查來估計平常錯誤。

用 Critical Decision Method 回放一筆具體事件，追問當時有哪些線索，以及哪項差異會改變決定。審核卡顯示候選狀態、兩段短證據、待裁定問題、可選操作。分開標記 observed、inferred、unknown。

練習。若兩種抽樣各審 10 筆，分別抓 6 筆和 2 筆錯，哪一組可以估全庫錯誤率？若審核時間差一倍怎麼比？

閱讀：[Snorkel](https://arxiv.org/abs/1711.10160)、[Core-set active learning](https://arxiv.org/abs/1708.00489)、[ACE 2005](https://catalog.ldc.upenn.edu/LDC2006T06)。前沿作業找一篇事件抽取論文，核對分數是 trigger 還是 argument，以及採用何種資料切分。

## 2.1 字詞、欄位、事件是不同層次

把「B 退掉週五的票，改訂週六」切成 token。BIO 以 B 表示 span 開頭、I 表示延續、O 表示欄位外。Transformer 先算每個位置各標籤的分數。線性鏈 CRF 加上相鄰標籤的轉移分數，Viterbi 逐位置保留每個標籤的最佳前綴與回溯指標，最後取總分最高序列。

**算例。** 第二個 token 的 I-DATE emission 為 3，B-DATE 為 2，前一個 token 是 O。O→I-DATE 扣 4，其分數為 -1。O→B-DATE 不扣，得 2。因此整體解選 B-DATE。用這個例子區分各字獨立分類與序列解碼。

NER 找出「週五」「週六」。事件抽取要把日期分別接到取消與改訂。Entity linking 要判「原票」是哪張，可用代碼、日期產生候選，再依旅客和來源重排。兩人同日各有一張時，日期不足以唯一對應。時間正規化也要保留原始說法。缺訊息發送時間，「明天」可能根本無法換算。

| 方法 | 適合 | 代價 |
|---|---|---|
| 模板與正規式 | 固定格式的確認信 | 版型改變要改模板 |
| 標註模型接序列解碼 | 類別固定且有訓練樣本 | 要設計標籤與資料切分 |
| LLM 加 schema 與來源 | 跨句、格式多、例外多 | 需額外驗證事實與引用 |

受限生成控制 JSON 形狀。Pydantic 核對型別、列舉和必填。業務層再查票券是否存在、旅客是否一致、引用是否支持取消。對同一案件分別評 span、欄位和完整事件，以免正確 JSON 掩蓋日期或對象錯誤。

## 2.2 弱標註怎麼學

Labeling function 對一筆輸入投類別或 abstain。組成的矩陣每列是案例、每欄是來源。多數決是一條基線。Snorkel Label Model 用來源的一致與衝突估可靠度，產生每筆資料的機率標籤。來源若共享同一訊號，獨立假設可能高估該訊號。

**算例。** 三條規則投已訂、已訂、候補。前兩條都只從同一封信抓「訂」字，第三條讀狀態欄。多數決得已訂。合併同源規則後是平票，此案值得送審。用獨立人工標註估各來源精確率，分信件模板報告。覆蓋率很高的規則仍可能在特定模板全錯。

## 2.3 把專家時間用在能改進系統的案件

Uncertainty sampling 以最大類別機率或 entropy 選案，仰賴分數能反映不確定性。Query by Committee 量模型分歧，會漏過一起犯錯的模型。Core-set 依案例向量和距離選能覆蓋不同區域的樣本，距離若抓錯特徵，稀有例外也可能被忽略。隨機抽查有助於估母體錯誤率。若改用分歧樣本估錯誤率，須說明樣本選擇偏差。

以「候補還是已刷卡」做審核卡，附原話、狀態欄與兩個候選。若兩種解釋都說得通，用 Critical Decision Method 回放具體案例，追問當時看到哪條線索、拿掉那條會不會改判。記錄規則來源和核准狀態。

**實驗。** 以相同審核預算比較隨機與分歧選案，加入一筆兩模型一致的錯例。報告平均找到幾筆錯、平均審多久、漏掉哪類錯。設計一筆「候補」誤讀的回歸案例。
