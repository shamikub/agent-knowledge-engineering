# 2.4 以專家審核提升標注品質

## 學習目標

完成本節後，你能夠：

- 描述 Critical Decision Method（關鍵決策法）的四個追問，並說明為何要回放具體事件而非詢問一般規則
- 設計一張含候選狀態、兩段短證據、待裁定問題、可選操作的審核卡
- 分辨 observed（觀察到的）、inferred（推論的）、unknown（未知的）三種標記，並說明混淆三者會造成的問題
- 用抽樣方法說明哪種審核策略可以估出全庫錯誤率，哪種只能找到困難案件

**先備知識**：讀完 2.3 節（弱標注）；知道什麼是精確率和召回率。

---

## 任務定義

專家審核（expert review）解決的問題是：**系統產生候選結果後，如何讓有限的專家時間產生最大的系統改進效益？**

```
輸入  → 模型候選結果 + 原始證據（訊息文字、票務資料）
過程  → 審核卡呈現 → 專家操作（接受/修改/拒絕）→ 標記回饋
輸出  → 更新後的資料集 + 錯誤模式分析
```

與弱標注不同，這裡的目標不是「標多」，而是「標對，且標最有學習價值的」。

---

## 架構說明

### 整體流程

```
候選生成
  │  模型輸出事件抽取結果，每筆附信心分數
  ▼
審核佇列排序
  │  依抽樣策略（主動學習或隨機）排序
  ▼
審核卡呈現
  │  每張卡顯示候選狀態、兩段短證據、待裁定問題
  ▼
專家操作
  │  接受（accept）/ 修改（edit）/ 拒絕（reject）
  ▼
標記回饋
  │  記錄操作、耗時、決策理由
  ▼
資料集更新
  │  正確案件加入訓練集；錯誤案件加入錯誤分析
  ▼
系統改進
     週期性重訓模型，更新 LF，調整審核優先序
```

## Critical Decision Method（關鍵決策法）

CDM 是一種結構化的認知訪談技術，用來從專家身上萃取**隱性決策規則**。核心做法是：不問「你一般怎麼判斷？」，而是**回放一筆具體事件**，逐步追問細節。

### 四個追問

| 追問 | 目的 |
|---|---|
| 1. 當時看到哪些線索？ | 找出專家實際用到哪些資訊（而非他以為自己用的） |
| 2. 哪個線索最關鍵？拿掉它會不會改變判斷？ | 找出決策的充要條件 |
| 3. 你排除了哪些可能性？為什麼？ | 找出反例與鑑別條件 |
| 4. 若這筆案件換一個情境（例如時間差一天），判斷會不會改變？ | 找出決策的邊界條件 |

### 訂位改票情境的 CDM 範例

**具體事件**：旅客訊息「我退掉 8 點那張，訂了 10 點」，系統只抽到一個 CANCEL 事件，漏掉 BOOK。

**追問過程**：

1. **當時看到哪些線索？**
   - 專家：「我看到『退掉』就知道是取消；『訂了』是另一個動作，系統只找了第一個動詞。」
   - 萃取出的規則：同一句話可以含多個事件，系統應允許輸出事件清單而非單一事件。

2. **哪個線索最關鍵？拿掉它會不會改變判斷？**
   - 專家：「如果沒有『訂了』，就只有取消，不會有 BOOK。關鍵是有沒有訂購動詞。」
   - 萃取出的規則：BOOK 事件的 trigger 詞（觸發詞）清單需要涵蓋「訂了、改訂、買了」等詞彙。

3. **你排除了哪些可能性？**
   - 專家：「我確認旅客說的是自己訂，不是幫別人訂。如果說『幫朋友訂』，agent 就不同了。」
   - 萃取出的規則：agent 欄位需要處理代理人情境。

4. **若換一個情境，判斷會改變嗎？**
   - 專家：「如果訊息是『我想退掉 8 點，可是 10 點有位嗎？』，第二個動作是詢問，不是訂票。」
   - 萃取出的規則：疑問句不觸發 BOOK 事件，需要語氣判斷。

## 算例：分歧抽樣 vs 隨機抽樣

### 情境設定

有 1,000 筆模型預測，其中：
- 950 筆模型信心高（P > 0.9），實際錯誤率 2%（約 19 筆錯）
- 50 筆模型信心低（P 在 0.4–0.6 之間），實際錯誤率 60%（約 30 筆錯）

審核預算：100 筆。

### 方案 A：分歧抽樣（全取低信心）

從 50 筆低信心案件全部取出，再取 50 筆次低信心，共 100 筆。

```
審核結果：約 60 筆錯（錯誤率 60%）
能找到的錯：~30 筆（低信心區的全部錯誤）+ ~1 筆（高信心區的抽查）
估全庫錯誤率：用 60% 代表全庫 → 嚴重高估（真實全庫錯誤率 ≈ 4.9%）
```

### 方案 B：隨機抽樣（從 1,000 筆均勻隨機取 100 筆）

```
審核結果：約 5 筆錯（與全庫 4.9% 相近）
能找到的錯：~5 筆
估全庫錯誤率：5% → 接近真實值（可信）
代價：找到的錯很少，對模型改進幫助有限
```

### 哪一組能估全庫錯誤率？

**方案 B（隨機抽樣）** 才能估全庫錯誤率，因為樣本是從母體均勻抽取。

方案 A 的樣本有選擇偏差（selection bias）——刻意選困難案件，無法代表全庫。若用方案 A 的錯誤率做報告，決策者會誤以為系統比實際差很多，可能做出過度反應。

### 計算需要多少樣本才能估出可信的全庫錯誤率？

用二項分布的信賴區間公式（Clopper-Pearson 或 Wilson）：

假設真實錯誤率 p ≈ 5%，希望 95% 信賴區間寬度 ≤ ±3%，需要的樣本數：

```
n ≈ z² × p(1-p) / e²
  = 1.96² × 0.05 × 0.95 / 0.03²
  ≈ 3.84 × 0.0475 / 0.0009
  ≈ 203 筆
```

若預算只有 100 筆，信賴區間約 ±4.3%，誤差範圍仍可接受但較寬。

### 建議策略：混合抽樣

```
100 筆預算分配：
  70 筆 → 主動學習（分歧/不確定性）→ 改進模型
  30 筆 → 隨機抽樣 → 估全庫錯誤率
```

## 審核卡設計

審核卡要讓專家在最短時間內做出最準確的判斷。以下是一張針對「訂位事件」的審核卡模板：

```
┌─────────────────────────────────────────────────────────┐
│  審核編號：REV-20240315-042        信心分數：0.51       │
│  模型候選狀態：CANCEL                                   │
├─────────────────────────────────────────────────────────┤
│  證據 1（旅客訊息，完整原文）                           │
│  「我退掉 8 點那張，訂了 10 點。」                      │
│                                                         │
│  證據 2（票務系統現況）                                 │
│  訂單 ORDER-20240315-0800：狀態 = 已購票，出發 08:00    │
│  訂單 ORDER-20240315-1000：狀態 = 無（尚未建立）        │
├─────────────────────────────────────────────────────────┤
│  待裁定問題：                                           │
│  這筆訊息觸發的是 CANCEL、BOOK，還是兩者都有？          │
├─────────────────────────────────────────────────────────┤
│  可選操作：                                             │
│  [A] 接受：只有 CANCEL                                  │
│  [B] 修改：CANCEL + BOOK（補上 BOOK 事件）              │
│  [C] 拒絕：此訊息無法判斷（需更多資訊）                 │
│  [D] 標記待討論：案件特殊，需團隊確認                   │
├─────────────────────────────────────────────────────────┤
│  決策依據（可選填，用於 CDM 分析）：                    │
│  ___________________________________________________    │
└─────────────────────────────────────────────────────────┘
```

**審核卡設計原則**：
- 兩段證據：一段是原始輸入，一段是系統現況（避免讓專家翻查外部系統）
- 待裁定問題：具體到只問一件事，不讓專家同時決定多個維度
- 可選操作：列舉，不讓專家自由填寫（降低不一致性）
- 決策依據：選填，但每週抽樣分析，用於 CDM 和 LF 改進

## 三種標記類型

在審核時，區分三種資訊來源可以防止「事後諸葛」污染訓練資料：

| 標記 | 定義 | 範例 |
|---|---|---|
| Observed（觀察到的） | 訊息原文中明確出現的資訊 | 「退掉」→ CANCEL trigger |
| Inferred（推論的） | 透過規則或常識推導出來的 | 「8 點那張」→ 推論是當天的班次 |
| Unknown（未知的） | 當時無法從現有資訊得出的 | 「10 點」是哪條線的哪個班次，沒有航線資訊無法確定 |

**為何要分開標記**：

若把 Inferred 和 Observed 混在一起，模型會以為所有欄位都是直接從文字讀到的，學到錯誤的信心。例如把推論出的日期當成 Observed，模型在沒有發言時間的情況下也會自信地填入日期，造成靜默錯誤（silent error）。

在 Label Studio 等工具中，可以用 `meta` 欄位或額外的選項記錄這三種標記：

```json
{
  "value": {"start": 3, "end": 7, "text": "8 點", "labels": ["TIME"]},
  "meta": {"certainty": "inferred", "requires": ["message_timestamp", "timezone"]}
}
```

## 工具

- **Label Studio**：開源標注平台，支援 pre-annotations（預先填入模型候選）讓專家做修改而非從頭標注
- **Inter-annotator agreement（標注者一致性）**：Fleiss' Kappa 或 Cohen's Kappa，衡量多位專家在同一批案件上的一致程度；Kappa < 0.6 通常意味著任務定義不清或審核卡設計有問題

```python
from sklearn.metrics import cohen_kappa_score

annotator_a = [0, 1, 0, 1, 0]  # 0=CANCEL, 1=BOOK
annotator_b = [0, 1, 1, 1, 0]
kappa = cohen_kappa_score(annotator_a, annotator_b)
print(f"Cohen's Kappa: {kappa:.3f}")
```

## 習題

**習題 1**：Critical Decision Method 追問

給定以下真實審核情境：

模型把「我票買好了，但不確定能不能退」標為 BOOK（信心 0.78）。資深客服人員說：「這不對，旅客只是想問退票規則，沒有要取消。」

請用 CDM 的四個追問，列出你會如何訪談這位客服人員，以萃取出可以轉化為 LF 的決策規則。

<details><summary>解答</summary>

**追問 1：你看到哪些線索？**
- 預期回答：「旅客說『不確定能不能退』，這是一個疑問，不是動作。」
- 萃取的規則：疑問語氣（能不能、可不可以、是否）後面的動詞不觸發事件。

**追問 2：哪個線索最關鍵？拿掉它會改變判斷嗎？**
- 預期回答：「如果說『我要退票，不確定要付多少費用』，前面有明確的動作，就是 CANCEL。」
- 萃取的規則：事件觸發需要**意志動詞**（我要/我想/幫我），不是疑問或條件句。

**追問 3：你排除了哪些可能性？**
- 預期回答：「我排除了 BOOK，因為買票已經完成（『買好了』），不需要再記錄為新事件。」
- 萃取的規則：過去式完成的動作（已購票）不觸發新事件，除非是修改或取消。

**追問 4：換一個情境判斷會改變嗎？**
- 預期回答：「如果說『我票買好了，但我現在要退』，就有 CANCEL 事件了。」
- 萃取的規則：「但我現在要退/取消」這類轉折句才觸發 CANCEL。

**可以轉化為 LF 的規則摘要**：
1. 疑問語氣 + 動作動詞 → ABSTAIN（不確定）
2. 意志動詞（要/想/幫我）+ 動作動詞 → 觸發事件
3. 完成式（已/了/好了）+ 無後續動作 → 不觸發新事件

</details>

**習題 2**：審核卡設計

以下是一個設計不良的審核問題：

> 「請判斷這筆訊息的事件類型、參與者、時間和票券代號是否正確，如有錯誤請修改。」

請說明這個問題的三個設計缺陷，並改寫成符合審核卡原則的版本。

<details><summary>解答</summary>

**三個設計缺陷**：

1. **一次問太多件事**：要求審核四個維度（類型、參與者、時間、票券），專家需要全部看完才能回答，認知負擔高，速度慢且容易漏判。
2. **開放式填寫**：「如有錯誤請修改」讓專家自由輸入，不同專家的填法不一致，資料難以自動處理。
3. **沒有指出具體疑點**：沒有告訴專家模型最不確定的是哪個欄位，專家不知道要重點確認什麼。

**改寫版本**：

```
待裁定問題（每次只問一件事）：
這筆訊息中，「10 點」指的是哪天的班次？

可選操作：
[A] 當天（2024-03-15）10:00
[B] 隔天（2024-03-16）10:00
[C] 無法從這段訊息判斷（需要更多資訊）
```

若有多個維度要確認，拆成多張卡（例如先確認類型，再確認時間），或在卡片上標注「主要確認項目」讓專家優先處理。

</details>

**習題 3**：選型與錯誤率估計

你有 200 筆審核預算，目前系統整體錯誤率未知。有同事提議全部用不確定性抽樣（取信心分數最低的 200 筆）；另一位同事提議全部隨機抽樣。

請說明：
1. 兩種方案各能帶來什麼好處
2. 若你的老闆要在月報中報告「系統目前的整體錯誤率」，哪個方案能回答這個問題？
3. 如果你只有這 200 筆預算，你會怎麼分配？

<details><summary>解答</summary>

**方案比較**：

| | 不確定性抽樣（200 筆） | 隨機抽樣（200 筆） |
|---|---|---|
| 找到的錯誤數 | 多（集中在困難案件） | 少（反映真實分布） |
| 能否估全庫錯誤率 | 否（選擇偏差） | 是（無偏估計） |
| 對模型改進的幫助 | 高（找到邊界案件） | 低（大多是容易案件） |

**老闆要整體錯誤率 → 只有隨機抽樣能回答**。

不確定性抽樣找到的錯誤率（例如 40%）不能代表全庫，因為樣本是刻意挑難的。若用 40% 報告給老闆，會誤導決策。

**200 筆預算分配建議**：

```
120 筆 → 不確定性抽樣：找出困難案件，改進模型
80 筆  → 隨機抽樣：估全庫錯誤率（80 筆的 95% CI 寬度約 ±5-6%，可接受）
```

月報告中：「整體錯誤率估計為 X%（±6%，基於 80 筆隨機樣本，95% 信賴區間）；另外針對低信心案件發現 N 筆系統性錯誤，已更新訓練資料。」

</details>
